#software/algorithms 
Recursion is a strategy for solving a problem where we reduce some problem to a smaller problem of the same type, repeating thus until we reach some trivial case that can be solved by other means, usually a known value. More specifically, recursion make use of *self-referential* definitions, where there is a base case (trivial solution) and recursive clause (self-referential bit). From a mathematical perspective, this is actually quite close to series relations, where $E_n = \dots E_{n-1}+ \dots$. From this perspective, doing a proof by induction to get a non-recursive definition for $E_n$ is equivalent to flattening a recursive definition into some neat(er) formula.
### Helper Functions
Often, it is neater to supply some helper function which calls into the recursive function for the first time, that supplies any arguments in their initial values.
### The Cost of Recursion
When writing recursive programs, there are a few major costs to performance. As a recursive call is just like any other function call, in that it has to put more things on the stack, often repeatedly, which can naturally lead to the reaching of stack depth limits. This can be due to improper implementation, such as not providing a base case or not checking it before the recursive call. However, even in properly implemented recursive functions, given a sufficiently large input, the algorithm may attempt to recurse more than is supported. Further, though highly optimised, the actions of pushing and popping to and from the stack does take time, which can add up very quickly, making some recursive implementations quite slow.
It is for this reason that when a recursive implementation can be replaced with a non-recursive one, the solution will run faster and with less memory.
A separate issue is that recursive calls can often be difficult or time-consuming to debug.
### Analysing Recursive Algorithms
Due to the recursive nature of some algorithms, they can be difficult to calculate the [time complexity](Time%20Complexity.md) of. However, we do have a method for finding it using recurrence relations.
If we set the time taken to perform $n$ iterations to be $C(n)$, we can define it recursively using smaller iteration counts and a base case.
For instance. if we were trying to use [binary search](Searching%20Arrays.md), we would set $n$ to the size of the array we were searching. Using binary search as an example, we would say that $C(n) < C(\lfloor n-1\rfloor) + 1$. From this, we can use a proof by induction, or trivially look at the graph of the values plotted by the recurrence relation. to see that $C(n) < \lfloor \log_2(n) \rfloor + 1$.
